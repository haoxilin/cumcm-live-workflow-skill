# CUMCM 真题全流程实战手册

沉淀自多轮真实竞赛实战、交叉审阅与 AI 自查表终审整改，聚焦**可执行的流程、坑位与质量门禁**，通用适配任意 CUMCM 题目。

## 触发条件

- 用户开始完整做一道真题（练手或正式比赛）
- 备赛训练：模拟完整流程
- 已出题、要求"按竞赛标准走完流程"
- 拿到成品论文，要求按 AI 自查表终审整改

## 工作区约定

- 题目材料放 `PROJECT_ROOT/<题号>/`：原题 PDF、格式规范 doc、附件/
- 建模产物（代码/npz/图）放题号目录；论文放 `题号/paper/`；结果 xlsx 放题号目录
- **附件模板只读**：填写时 load 原模板写单元格另存，不覆盖原附件

## 流程总览（按序执行）

```
0. 环境检查 → 1. 读题+格式规范 → 2. 逐问建模+出图（至少8图）
→ 3. LaTeX 论文 → 4. 交叉审阅（≥2轮）→ 5. 填 result 模板
→ 6. AI 自查表驱动终审 → 7. 清理+打包
```

## 1. 读题 + 格式规范

### 题意理解优先（最高优先级教训，任何题目通用）
- **题干明写的物理事实必须建模进去**：题面给出物体有宽度/厚度/形状 → 碰撞、干涉、间隙类判定必须用其**真实几何**（矩形/多边形/角点-中心线距离判据），严禁简化为"中心线/质点间距"判据——后者会漏检真实干涉，导致终止时刻、临界参数等关键结果整体失真
- **几何初始条件必须用解析公式独立验证，禁止只信单一来源**：凡能用公式从题干数字推出的参数（如半径=螺距×圈数、长度=孔距+2×孔心距、角度=弧长/半径），一律推导核对一遍，不能只信视觉读图
- **后问对前问误差高度敏感**：初始条件错→中间判据错→后续结果连锁全错；问题间耦合必须每步验证
- **无官方答案时的题目自查（真实比赛核心）**，读完题后逐条执行：
  1. **题干数值→解析公式独立推导**：把题面每个数字代入公式算一遍，凡是能算出来的参数不许依赖读图/猜
  2. **单位与几何自洽检查**：所有长度/时间/速度换算成同一单位系；画示意图核对几何关系
  3. **边界情形推演**：取极端参数（最大/最小）走一遍模型，看结论是否符合物理直觉——能抓出大部分"模型没建对"
  4. **多方法交叉验证**：同一结论至少两种独立途径（解析式 vs 数值扫描 vs 特例验证），一致才算数
  5. **把"题面明写的物理事实"列清单**：写进代码注释/文档，建模时逐条对照是否全部体现

### 格式规范要点（以当届官方《格式规范》为准）
- 电子版论文**第 1 页必须为摘要专用页**（页码自摘要页从 1 起、页脚中部）
- 正文页数以当届规定为准（如 2026 修订稿：正文 ≤30 页，附录页数不限）；**无目录**
- 附录：**支撑材料文件列表 + 全部完整可运行源程序**（缺失可取消评奖资格）；支撑材料文件列表必须与实际压缩包内容对齐（zip 几十个文件而附录只列几个 = 评委抓包点）
- 电子版 PDF ≤20MB；支撑材料 ZIP/RAR ≤20MB
- 匿名三查：全文/代码/PDF 元数据（author/title 为空）无学校、姓名、赛区、用户名、绝对路径
- 读完后产出《题目分析报告.md》+《术语表格.md》（或按用户要求延后）

## 2. 建模 + 出图（核心循环）

每个问题固定两步：**先明确思路 → 再建模出图**，逐问重复，最后才写论文。

### 出图规范（Nature 风格，务必达标）
- matplotlib 300dpi，**PNG+PDF 双格式**，serif 字体
- 坐标轴必须有"物理量+单位"；多曲线必有图例；热力图 colorbar 标注物理量
- 图题在下方居中"图X ..."
- 总图数 ≥8 张；每图生成后**视觉模型 QA**（确认无乱码/贴边/数据矛盾）
- 宽表格（>6列）必须 `\resizebox{\textwidth}{!}` 包裹或 `tabularx` 自适应换行，否则右侧贴纸边（实测踩坑）

### 数值严谨性红线（实测踩坑，通用）
- **链条/连续系统类题目：不要信单点迭代的"碰撞/临界"结论**。弯曲段求解器会跳分支产生伪解（参数突变、数值爆炸）。必须用：①全局搜索约束可解性 ②时间连续初值重解 ③解析封闭解交叉验证
- **速度场用弧速法/解析传播，不用位置差分**：急弯处差分低估弧速可达 7% 量级
- 解析近似式 ≠ 数值精确解时：以数值为准，解析式放"机理分析"作定性解释，行文不要显得"用数值凑"
- **自建验证基准（无官方答案时）**：用解析特例（退化情形/对称性）、极端参数、第二独立实现建立基准，做完每问先对表

## 3. LaTeX 论文

- ctexart + xelatex，`\documentclass[zihao=-4,UTF8]{ctexart}`（小四正文）
- 全宋体：`\setCJKmainfont{SimSun}`；标题靠字号+加粗区分（SimSun 无粗体，会伪粗，正常）
- 页码必须显式：fancyhdr `\fancyfoot[C]{\thepage}`（ctexart 默认可能不显示页码，实测踩坑）
- 摘要页：标题居中 + "摘 要"居中加粗小标题 + 正文左对齐 + 关键词顶格
- 公式：向量加粗 `\mathbf{A}`、范数 `\lVert`；推导分步 align 展示，代数变换要"一目了然"
- 交叉引用：编译两次确认无 undefined；**所有图/表/式引用一律 `\ref`/`\eqref` 自动编号，严禁硬编码"图N/表N/式N"**（插入新图表后硬编码编号会整体错位）

### 论文结构硬性要求（源自韩中庚《数学建模竞赛论文的写作方法》，逐条对照检查）
- **敏感性分析不可缺少**：模型检验必须有——误差分析（模型/数据/舍入误差）验准确性 + 敏感性分析验可靠性（关键参数小扰动→结论变化量化列表）。**敏感性数值必须实跑脚本得出，禁止凭空填**（且注意扰动响应可能不对称，如实呈现）
- **假设必须"讲理"**：每条假设补必要性+合理性+正文引用，禁止干条目罗列；数量 3~4 条为宜，假设过多显模型脆弱
- **模型评价四要素齐全**：优点（不过分夸张）+ 创新点 + 缺点（不回避）+ 改进方向（针对问题的想法）
- **层次标题排比**：同一层标题用词类型相同、语义相关；标题内禁手写"问题X"前缀（与自动编号重复）
- 评阅四标准：假设合理性/建模创造性/结果正确性/表述清晰性——每章自查
- 摘要"重中之重"：高度压缩、突出特色创新点、**含每问量化结果**、800~1000 字（2026 自查要求）、不出现复杂公式表格
- 问题重述是"正确解读后的重新表述"而非复制；避免"用软件编程计算得到结果如下表"直接丢图无解释
- **问题分析=叙述推演式**：按"已知→推导→结果"链条叙述各问思路，每问独立成段；禁止技术选型清单/bullet 罗列
- **模型假设=极简**：每条一句话不带解释；"讲理"体现在正文引用处而非假设条目本身

### 去 AIGC 特征（正文 + 代码，评委会抓）

#### 正文语言（四大维度）
- **弱化路标式过渡**：删"首先/其次/值得注意的是/综上所述/基于上述分析"；章节标题本身是路标，正文直接切入；"A需…；B需…"排比清单 → 改因果链（"因为…所以必须…"，每条交代理由）
- **打破完美对称句式**：长短句交替——复杂推导用长句、关键结论用短句加重；加入作者视角词（"经检验/实际上/写程序前先比较过"）模拟思考停顿
- **注入作者主体性**：模型选择交代权衡过程（"若简化为…误差约10⁻⁴，但递推中误差沿链累积…保险起见用精确式"）；局限要具体化（给出数字和经验判断，忌"未考虑摩擦"式空话）；可留探索痕迹（"一开始只检测…程序跑完显示无碰撞，但和物理直觉相悖…回头检查才发现…"）
- **摘要去模板化**：忌"每问一段"标准模板；合并叙述、突出核心创新；关键词用体现具体技术手段的词，不用宽泛词

#### 附录代码（六大特征 + 对策）
- **特征1 教科书式注释**（每行注释、docstring 完美统一）→ 只留"为什么"和"踩坑记录"，删"做了什么"
- **特征2 命名完美主义** → 循环内允许单字母/缩写；不同文件风格允许差异；保留无害临时变量
- **特征3 中英混杂特定句式** → 纯中文或纯英文口语化备注
- **特征4 缺乏个性化痕迹** → 加版本迭代注释（# v2: 修正了碰撞检测的边界bug）；保留被注释掉的旧方案；魔法数字注明来源
- **特征5 输出过于规整** → 打印加非正式进度提示；验证内联在 `__main__` 块；打印与解析/已知答案的对比备注
- **特征6 文件组织过于清晰** → 保留"复制粘贴+微调"的合理冗余，不必强行抽公共模块；代码内注明中间文件依赖
- **红线**：不要故意制造 bug；"不完美"只体现在注释/命名/结构痕迹，数值必须正确
- **精确数字克制**：机器精度级数字只在验证部分出现一次；不罗列精确扫描区间，写"对可行域内不同取值验证"
- 机理小节标题各异，不机械重复；不自夸，删"精确性/理论深度/逻辑闭环"式自我评价

### LaTeX 编号与图表规范（审阅实测，必看）
- **图表引用必须 `\ref`/`\eqref` 自动编号**：统一 `\label{fig:xx}`/`\label{tab:xx}` + 正文"图\ref{fig:xx}"；若已硬编码，编译后用 `pdftotext` 对比实际编号逐一修正
- **双子图标准格式**：图题两行居中——第一行"图X: 总图名"，第二行"(a) 子图1说明；(b) 子图2说明"（caption 内 `\\` 换行）；图内子图标题也要有 (a)(b) 标记；**caption 必须加 `justification=centering`**（否则多行图题第二行左对齐）
- **附录编号体系**：`\section*{附录}`（不编号）+ `\subsection*{附录A：...}`（手写字母），引言部分不占字母编号（避免"两个附录A"）
- **编号体系 v7（章节 vs 列表 vs 公式三档区分）**：
  - 章节标题：无括号数字递进（1 / 1.1 / 1.1.1）
  - 列表条目（模型假设/任务列表/算法流程）：**`enumerate` + `label=(\roman*)` 罗马小括号** `(i)(ii)(iii)`——**不能用阿拉伯 (1)(2)**：公式编号也是小括号阿拉伯，"式(4)"与"第(4)条"会混淆
  - 公式：`\begin{equation}` 自动 `(1)(2)(3)`；**多行 `align` 必须 `\notag` 只留一个编号**（三行约束不加 \notag 会各占一个公式号且无人引用，公式号整体跳跃）
- **TeX 细节**：正文中文里的 `#` 必须转义 `\#`；`\boxed{}` 除非风格要求否则别用
- **竞赛论文禁用"与官方答案一致"表述**：验证必须建立在物理合理性/解析推导/双判据互证上（"与解析推导吻合""双重判据互证"）

## 4. 交叉审阅（关键增值环节）

用户会把论文交给其他 AI 审阅，反馈逐条处理。处理模板：

```
| 意见 | 处理 |
|---|---|
| 每条意见 | 定位→核实（跑代码/视觉QA）→修改→说明 |
```

- **先核实再改**：审阅者可能看错/看旧版——用视觉模型或像素分析确认，如实说明
- 审阅意见分类：①格式/排版（直接改）②数据矛盾（跑代码验证）③逻辑跳跃（补证明）④AI味（删套话）
- 摘要/正文/表格/图注**同步更新**，避免只改一处留下不一致
- 每轮处理完重新编译 + 视觉抽查关键页

## 5. 填 result 模板

- openpyxl load 原模板 → 写数据单元格 → 另存新文件（保留 sheet 名/表头/行列布局）
- 结果保留 6 位小数
- 验证：行数列数与模板一致、无错误值（#VALUE 等）、与论文数值一致
- 行映射通用提示：先按模板表头定位"龙头/第k节/龙尾(后)"所在行（位置表通常 x/y 两行一组、速度表每把手一行），抽查关键单元格与论文表格逐位比对

## 6. AI 自查表驱动终审（2026 新版 AI 合规 + 证据链核查）

触发：拿到成品论文，要求"按自查表审查/自查"或提交前终审时。

### 6.1 2026 AI 新规硬性红线（评委第一关，违者可取消评奖资格）
- **参考文献之前必须有「AI 工具使用声明」**，二选一模板：未使用（"本参赛队在竞赛过程中未使用任何AI工具。"）/ 使用了（"……主要用于【简要用途，如语言润色、代码调试等】，详细使用情况见支撑材料。"）——缺声明即"不符合规定"
- 支撑材料必须含 **`AI工具使用详情.pdf`**（①工具名称/版本 ②使用目的环节 ③提示方式与过程 ④采纳/人工修改/核验情况，语言润色除外）
- **论文、支撑材料、附录文件列表三处必须对齐**
- 摘要必须**单独一页、含每问量化结果、800~1000 字**；正文页数符合当届规范
- 匿名三查：全文/代码/PDF 元数据

### 6.2 自查表 26 条六维度框架（逐条判定：合格/存在问题/待核实）
一、AI 新规合规(4) 二、AI 幻觉与数据真实性(4) 三、建模逻辑与题意适配(5) 四、求解及结果合理性(3) 五、官方写作规范(6) 六、官方排版与页数(4)
（自查表 docx 用 python-docx 提取段落+表格，表格行即 26 条核查条目）

### 6.3 证据链核查法（不轻信论文自述，每条结论都要"能跑出来"）
- **范文/参考解答校准**：若存在获奖范文或公开参考解答，grep 其关键数字与论文逐位对比；多篇参考冲突时 → 独立复算裁决
- **独立复算**：从零实现关键结论（不调用论文代码），同时复算"另一种解读"是否成立 → 判定分歧根源，给论文加限定句防御（明确本文采用哪种约束/判据设定）
- **数据文件抽查**：按模板行映射抽查结果 xlsx 单元格与论文表格逐位比对
- **图表目检**：逐图 read_image 核对图注数值 vs 正文（阈值标注口径、时间范围、图例单位——实测常抓到图文不符）
- **PDF 程序化测量**（PyMuPDF）：每页首行/字数看结构；bbox 检测表格越界（max x ≤ 右边距）；元数据匿名；全文 compact 去空白匹配关键数字（规避字体间距导致匹配失败）
- **摘要字数程序化统计**（汉字数 vs 总字符数口径）

### 6.4 五段式自查报告模板
1. 自查结果汇总表（26 条 × 结果/位置/问题简述/整改建议）
2. 整体合规判定（一句话结论：能否提交 + 是否踩取消资格红线）
3. 问题分级汇总（🔴致命 / 🟠一般缺陷 / 🟡轻微瑕疵）
4. 优先级整改清单（按扣分权重排序，每条给到具体位置+改法）
5. 官方规范适配度与潜在风险预警（含"解释分歧风险"：结论与部分参考解答相左时如何防御）

## 7. 终审整改实操技巧

- **诚实重生成**：图表数据缺失/图文不符时从代码重算重绘，绝不手绘/编造；重生成值与既有结论互证（如扫描交点与二分临界值差异 <0.1%）；扫描数据 npz 存支撑材料供复现
- **敏感性实验必须实跑，且注意非对称性**：扰动 ±1.5% 级别的响应可能正负不对称（临界接触构型对"变宽/变窄"灵敏度不同），如实呈现并解释；脚本入附录，结果存 npz
- **叙事与附录代码一致性**：正文对早期方案/判据的描述必须与附录代码注释一致（如"旧判据得到明显偏早的时刻"而非"全程无碰撞"），评委必对照附录代码抓矛盾
- **误差百分比口径**：明确分母（以真值为基准 vs 以粗采样为基准），统一口径表述，避免"误差13%"歧义
- **编号体系 v7**：列表 `(\roman*)` 罗马小编号区分公式 `(1)(2)`；align 多行公式 `\notag` 只留一个号；图表引用全部 `\ref/\eqref`
- **LaTeX QA 管线**：两遍 xelatex → 日志查 `^!`/undefined/`Overfull \hbox` 分级（正文段落 >15pt 必修，代码附录长行可忽略）→ PDF 文本层抽查关键内容（AI 声明页码、新表页码、量化数字出现次数）
- **宽表排版**：文件列表/长内容表格用 `tabularx` X 列自动换行（比 resizebox 缩字清晰），超宽内容合并行
- **整改后联动检查**：摘要数字 ↔ 敏感性表 ↔ 附录脚本 ↔ 支撑材料 npz 四者一致；自查报告追加"整改完成记录"（含每项修复+成品页码）
